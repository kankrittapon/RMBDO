## Next concrete step — recipe tree / buy-vs-gather per ingredient

This is the piece the user explicitly asked for that is **not built yet**.
What's known and already scoped (see the earlier exploration in this
session's transcript, and `README.md`'s "Known gaps"):

- bdolytics has this data on each recipe's own detail page
  (`bdolytics.com/en/crafting/<id>:<hash>`) — confirmed via manual
  browsing: a full nested ingredient tree down to base materials, with
  Crafting Cost / Crafting Profit / Profit-per-Hour / Time already
  computed per node (screenshot captured during exploration, not just
  described).
- The list-page scraper (`collector/src/scrapers/crafting.ts`) does not
  currently capture each row's detail-page link (only `innerText`, no
  `href`) — that needs adding first so recipe IDs are known.
- Scraping detail pages for all 854 recipes daily is very likely to hit
  the Cloudflare rate-limit/block this project has already hit twice
  before (documented in README) — scope this to on-demand (scraped live
  when the user clicks into a specific recipe in the Life Skill Hub, not
  bulk-collected) rather than a bulk daily job, unless proven safe
  otherwise.
- New schema needed: something like `crafting_recipe_ingredients`
  (recipe_id/name, material_name, quantity, is_sub_recipe, sub_recipe_id)
  — not designed yet, just scoped.
- UI: a detail drawer/modal on each Life Skill Hub row showing the
  ingredient breakdown once scraped.
